01 Sitemap & wireframe outline

The site is organized around one promise: a single dark-mode home for every anime, manga, comic and webcomic, with a reading-grade UI on top of the most complete open metadata sources. The tree below maps every public route plus the internal sub-apps that are intentionally quarantined.

┌─ kira.app/ — Discovery homepage (SSR + ISR 30min) │ ├─ /ask — AI Smart Search (chat-style, LLM-ranked) │ ├─ /library — User shelves: reading / planned / completed │ ├─ /title/:slug — Title detail (manga, anime, comic, webcomic) │ │ └─ /title/:slug/character/:slug — Character wiki + gallery │ ├─ /read/:chapter — Immersive reader (vertical / LTR / RTL) │ ├─ /watch/:episode — Embedded official streaming (link-out by default) │ ├─ /shorts — TikTok-style vertical feed │ ├─ /me — Profile: streaks, badges, XP, quests │ ├─ /sitemap.xml · /robots.txt — Partitioned per type; mature paths disallowed │ └─ /api/{jikan, anilist, search, age-gate} — Proxies + AI SSE stream │ ├─ [ AGE-GATE WALL · kira_18 cookie ] ────────────────────────────────────── │ ├─ kira.app/m/ — Mature library landing (on same domain) │ ├─ /m/title/:slug — Adult-rated title detail │ └─ /m/character/:slug — "Hot character" galleries, upvote/downvote │ └─ SEPARATED SUB-APPS ├─ m.kira.app — Optional sub-domain split (production / ads-safe) ├─ studio.kira.app — Creator portal · KYC, uploads, analytics └─ api.kira.app — Public read-only API · rate-limited

03 18+ age-gate · SEO architecture

The mature library exists, can be accessed, and never touches the main domain's indexable surface. This is the bit that protects ad-network deals, App Store reviews, and Google brand-safety classification. Two architectures are supported; MVP runs the lighter one.

Architecture A · Same-domain isolation MVP

Anonymous request │ ▼ ┌──────────────────────┐ │ middleware.ts │ runs on the edge for every req │ match: /m/* /mature │ └──────────┬───────────┘ │ ┌───────┴───────┐ │ │ cookie? no cookie │ │ ▼ ▼ allow 302 → /age-gate?return=... │ │ ▼ confirm 3 consent rows /m/* │ │ ▼ │ POST /api/age-gate │ Set-Cookie: kira_18=1 │ httpOnly · secure · sameSite=lax │ maxAge: 90 days │ │ ▼ ▼ mature library redirect to /m/*

Architecture B · Sub-domain split PRODUCTION

Once revenue justifies the ops cost, move /m/* to m.kira.app. The age-gate flow is identical; the win is that Google sees two distinct sites and never lets mature pages contaminate kira.app's search profile. Most ad networks classify by registered domain — having a second one keeps your main inventory clean.

SEO isolation rules

1 · No crawl, ever

robots.ts disallows /m/, /mature/, /api/, /age-gate. Every mature page also emits noindex,nofollow via metadata.robots as belt-and-braces.

2 · No cross-linking

Main feed never includes mature titles. The only entry-point on kira.app is the deliberate "18+" link in nav — a single anchor with rel="nofollow" + data-mature.

3 · No shared sitemap

Mature pages are excluded from sitemap-titles.xml. If you go sub-domain (B), mature gets its own sitemap on m.kira.app/sitemap.xml.

4 · No shared cookies

The recommender, watchlist and read-progress run on a session keyed by sub-domain (architecture B) or a separate session ID + path-scoped cookies (architecture A). Mature reads never influence main-feed recs.

5 · Hard rating filter

Ingestion sets title.mature = true from MangaDex contentRating ∈ {erotica, pornographic} or AniList isAdult. Every query against the main feed is filtered server-side.

6 · OG / Twitter cards

Mature pages strip og:image and use a generic "18+ restricted" placeholder. Embeds on Discord/Slack never reveal cover art.

Implementation checklist

  • Edge middleware on /m/* + /mature/* — 302 to /age-gate?return=<path> when kira_18 cookie absent.
  • Cookie: kira_18=1, HttpOnly, Secure, SameSite=Lax, 90 days. Set only via POST /api/age-gate with explicit consent payload.
  • Age-gate page: three mandatory consent rows (18+, not in public, understand main feed stays SFW). No skip path that auto-confirms.
  • robots.txt disallows mature paths. sitemap.xml excludes them. meta robots noindex,nofollow on every mature page.
  • nofollow on the single nav "18+" link. No mature title appears in /sitemap.xml, RSS feeds, or any internal recommendation surface.
  • Search index — query path always filters WHERE mature = false unless the request originates from /m/*.
  • Production cutover — once monetizing, migrate to m.kira.app. Cookie domain stays per-host; auth uses cross-domain SSO via JWT.
  • Compliance review — confirm with current ad-network ToS before going live in your region. App Store requires age-gate + rating >= 17+ in store listing for the mature feature.
