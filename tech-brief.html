The engine room.

A focused brief on how KIRA gets built and how its content empire scales without losing speed or SEO. Sitemap, user flows, AI integration map, automated SEO content engine, database schema notes, and a defensible tech stack.

01 Sitemap & user flow

Three flagged entry points feed every user into the same flywheel: discover → consume → react → share. The Creator Portal and the Mature library are deliberately quarantined sub-apps so they don't pollute the main domain's SEO or ad-network compliance.

03 Database & service architecture

Read-heavy by 200:1. Static catalog gets pre-rendered at the edge (the SEO play); user-state and writes go through an event bus.

Edge / CDN → ISR'd title + chapter pages, sitemap.xml, OG cards, robots App tier (Next.js) → /api routes; server actions for write paths Read DB → Postgres (titles, chapters, characters, users, social) Search → Meilisearch + pgvector (semantic + lexical, hybrid scoring) Event bus → Kafka / Redpanda → recommender, analytics, recap Object store → S3 + Cloudflare R2 for page images, motion clips, shorts Cache → Redis hot-keys: feed, leaderboard, streaks AI services → LLM cluster for /ask, synopsis rewrite, panel detection

04 AI integration map

CHAT · REALTIME

Smart Search ("Ask KIRA")

LLM ranker over a hybrid retrieval (BM25 + pgvector). Each query rewritten into a structured filter: {tags, vols≤30, completed, art_tier}. We log refine turns as preference signals. Streams in <1.4s p50.

CONTENT

Recommender · "For You"

Two-tower model: user-progress embeddings × title embeddings. Re-ranked by an LLM that explains the pick ("if you liked Berserk"). Cold-start uses Jikan tag overlap.

VISION

Panel detector

Per-chapter, every page gets bounded-box panel detection + OCR for JP text + SFX recognition. Feeds the Shorts Studio "AI-pick 6 panels", and the Read-Along overlay.

LANG

Read-Along JP tutor

OCR'd kanji → MeCab tokenize → JMdict gloss + furigana + speaker. Words a user looks up bank into spaced-repetition decks tied to their JLPT level.

REVIEW

Trust & safety

Creator uploads go through CLIP-based content classifier (mature, gore, IP-likeness). Anything ambiguous queued to human review; appeal pipeline visible in the Creator Portal.

GEN

Synopsis & character rewriter

See §05 — this is the SEO engine. Strict source attribution; output diffed against the original to prevent paraphrase plagiarism.

05 Automated SEO content engine

Wikipedia, MAL and Fandom rank for every title. The engine's job is to produce unique, sourced, fan-voice copy Google rewards — and to ship it without a copywriter touching it.

┌────────────┐ ┌────────────┐ ┌───────────────┐ ┌──────────────┐ ┌──────────────┐ │ source │──▶│ extract │──▶│ KIRA rewriter │──▶│ similarity │──▶│ ISR publish │ │ (Jikan/AL) │ │ facts │ │ (LLM, brand) │ │ guard ≤25% │ │ + sitemap │ └────────────┘ └────────────┘ └───────────────┘ └──────────────┘ └──────────────┘ │ on-fail ▼ human review queue
  1. Extract facts from Jikan / AniList — author, status, vols, demographic, character list. Never copies prose.
  2. Brand-voice rewriter (LLM with KIRA system prompt) writes synopsis, character lore, episode recaps. Tone: kinetic, present-tense, spoiler-safe.
  3. Similarity guard: rewritten text is embedded and compared against all known wikis/MAL pages. If >25% cosine similarity to any single source, regenerate.
  4. Schema.org markup attached: TVSeries, Book, ComicSeries, Person, plus Review aggregates from upvotes. JSON-LD baked into the SSR head.
  5. ISR publish: pages re-render on chapter drop. sitemap-titles.xml, sitemap-chapters.xml, sitemap-characters.xml are partitioned per type. RSS feed per series for SEO and discovery.
  6. Watch loop: GSC API ingests CTR / impressions weekly; underperformers re-enter the rewriter with a different angle.
★

No scraping. No prose copying. We license catalog metadata via Jikan's terms + commercial AniList agreement, and only structured facts move through the pipeline. The brand-voice copy is wholly KIRA-original — the similarity guard is the kill-switch.

06 Tech stack & performance

Strict budget: LCP < 1.5s on a mobile mid-tier device, TBT < 100ms, CLS < 0.05. Every choice below serves that ceiling.

FRONTEND

Next.js 15 (App Router) with React Server Components. Static + ISR for catalog; Server Actions for writes. TypeScript, Tailwind + tokens, shadcn/ui primitives forked into the KIRA design system. Motion via Framer Motion + view-transitions API for buttery cross-page nav.

RENDERING

Edge ISR on Vercel + Cloudflare in front. Title pages cache 24h, chapter pages 5min after drop. Reader pages stream image manifests; the actual page imgs are image/avif with fetchpriority="high" on visible panels.

BACKEND

Postgres 16 (Neon) for canonical data + pgvector. Redis for hot keys. Meilisearch for fast lexical. S3 + Cloudflare R2 for images. Inngest for cron + event workers (ingestion, rewriter). tRPC internally where servers need to chat.

AI

Smart Search and the rewriter call a tiered LLM stack — fast model for retrieval re-rank, frontier model for content generation. Embeddings via text-embedding-3-large; vision via custom panel-detector (YOLOv8 fine-tuned on a hand-labeled manga corpus).

VIDEO

Shorts Studio renders client-side with WebCodecs + WebAssembly FFmpeg for <30s clips; longer renders go to a Lambda fleet. Auto-watermark, tag injection, and platform-aware aspect crop at upload time.

OBSERVABILITY

Sentry for FE + BE errors, OpenTelemetry to Honeycomb, Datadog RUM for Core Web Vitals per route, PostHog for product analytics + feature flags. SEO health: weekly GSC API pull → underperformer report.

07 Risks & open questions

  1. Licensing. The "Where to Watch/Read officially" directory is fine; hosting chapters needs publisher deals. MVP: licensed webcomics + creator-portal originals only. Catalog metadata for everything else, links out to Crunchyroll/MangaPlus.
  2. Shorts Studio + copyright. Fan-clipped panels from licensed manga is a fair-use gray zone. Mitigation: opt-in by publisher (rev-share program), aggressive takedown SLA, auto-watermark, source attribution baked into every export.
  3. Read-Along scope. JLPT N5–N3 is realistic at launch. N2/N1 idiomatic / SFX is hard — start with the kanji + kana + meaning loop, defer audio pronunciation to phase 2.
  4. Mature isolation. Strict sub-domain split + ad-network-safe main app is non-negotiable; cookies, recommender, and avatar must not bleed across.
  5. Creator monetization timeline. Phase 1 = portal + uploads + analytics. Monetization (rev share, tipping, paid chapters) is phase 2 once we have publisher deals and KYC infra.
